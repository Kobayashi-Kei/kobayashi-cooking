# 小林の台所 プロダクト要件定義書（ドラフト v1）

## 1. 概要

小林恵大（こばやしけいた）・小林唯花（こばやしゆいか）夫婦が作った料理を、写真とひとことメモで気軽に記録・閲覧できる身内向けWebサイト「**小林の台所**」を作る。

- 公開範囲：身内用（誰でもURLを知れば見られるが、積極的な外部発信は想定しない）
- ホスティング：GitHub Pages
- 実装方針：静的サイトのみ。画像も含め全コンテンツをリポジトリで管理・配信する（外部ストレージ・DB・サーバーサイド処理なし）

## 2. 目的・ゴール

- 夫婦それぞれが作った料理を記録に残し、後から見返して楽しめるようにする
- 「今まで何を作ったか」を一覧・検索的に振り返れるようにする
- 更新のハードルを低く保ち、気が向いたときにサッと追加できる仕組みにする（無理な継続を前提にしない）

## 3. ターゲットユーザー

- 小林恵大さん・唯花さん本人（記録する側・見返す側）
- ごく身内（家族・親しい友人など）が閲覧する程度を想定。不特定多数への公開・SEO・SNS拡散は目的としない

## 4. コンセプト・デザイン方針

- トーン：**温かみのある手書き風**。家庭的でほっこりした雰囲気、イラスト的な装飾、柔らかい配色・フォント
- 「台所」というタイトル通り、堅苦しくない・親しみやすいレイアウトにする
- 情報量よりも「見て楽しい・めくって楽しい」体験を優先する

## 5. コンテンツ粒度（1品あたりの情報）

**写真＋ひとことメモ程度**のライトな記録に振り切る。

各料理エントリに持たせる項目（案）：

| 項目 | 必須 | 備考 |
|---|---|---|
| 料理名 | ◯ | |
| 写真 | ◯ | 1〜数枚。リポジトリ内 `images/` 配下で管理 |
| 作った人 | ◯ | 恵大 / 唯花 |
| カテゴリ | ◯ | 和食・洋食・中華・デザート など（複数選択可） |
| 作った日 | ◯ | 並び替え・後日の振り返り用 |
| ひとことメモ | 任意 | 感想・工夫点など自由記述 |

※レシピの詳細な手順・分量は**スコープ外**（気軽さを優先するため）。将来的に書きたくなった料理だけ個別に厚くする、程度の余地は残す。

## 6. 分類・閲覧軸

以下2軸を両方サポートする。

1. **作った人で絞り込み**（恵大さん / 唯花さん / すべて）
2. **カテゴリで絞り込み**（和食 / 洋食 / 中華 / デザート / その他 など。複数タグ可）

軸は掛け合わせ可能（例：「唯花さんが作った和食だけ見る」）とし、トップまたは一覧ページ上のフィルタUIで完結させる。全文検索・タグ自由入力は初期スコープでは不要（カテゴリを増やす形で対応）。

## 7. サイト構成（サイトマップ）

```
/                … トップページ
/dishes/         … 料理一覧ページ（フィルタ機能つき）
/dishes/xxx.html … 料理詳細ページ（写真＋メモ）※1件1ページ
/about/           … サイトについて（任意・簡易な紹介文）
```

- **トップページ**：サイトのコンセプト、最近追加された料理（新着数件）、一覧ページへの導線
- **料理一覧ページ**：全料理をカード形式（写真サムネ＋料理名）で表示。「作った人」「カテゴリ」でフィルタ可能
- **料理詳細ページ**：写真（複数可）、料理名、作った人、日付、ひとことメモ
- **Aboutページ**：サイトの趣旨、夫婦の簡単な紹介（任意、最悪スキップ可）

## 8. 機能要件（初期スコープ）

- [ ] 料理一覧の表示（カードグリッド）
- [ ] 「作った人」フィルタ
- [ ] 「カテゴリ」フィルタ
- [ ] 料理詳細ページの表示
- [ ] レスポンシブ対応（スマホで見る想定を優先）
- [ ] 新着順・日付順の並び替え

### スコープ外（v1では作らない）

- ユーザー認証・コメント機能・いいね等のインタラクション
- 全文検索
- 詳細なレシピ（分量・手順）ページ
- 画像の自動リサイズ等のビルドパイプライン高度化（必要になったら検討）

## 9. コンテンツ更新フロー

- 更新頻度：**不定期**（気が向いたときにまとめて、または1品ずつ追加）。運用ルールは定めない
- 追加方法：料理ごとに1つのデータファイル（例：Markdown or JSON、frontmatterに料理名・作った人・カテゴリ・日付・メモ）＋画像を `images/` に配置し、リポジトリにコミットするだけで反映される状態を目指す
- 「気軽さ」を最優先するため、新規ページのHTMLを毎回手書きするのではなく、料理データを1件追加するだけで一覧・詳細ページに反映される仕組みにする（下記の技術方針を参照）

## 10. 技術方針（前提条件）

- ホスティング：GitHub Pages
- コンテンツ：**静的サイトジェネレータは使わず、素のHTML/CSS/JavaScriptで構築**（ビルド環境・ビルド用CIを持たない）
  - 料理データは `data/dishes.json`（またはそれに準じる1ファイル）に配列で保持し、一覧・詳細ページはJSで読み込んで描画する
  - 料理を追加する際は、このJSONに1エントリ追加し、画像を `images/` に置いてコミットするだけで反映される状態にする
- 画像：すべてリポジトリ内で管理・配信（外部の画像ホスティングは使わない）
- 採用理由：更新頻度が低く・ページ構成もシンプルなため、ビルドツールの学習・運用コストをかけず、GitHub Pagesにそのまま置くだけで完結する構成を優先した
